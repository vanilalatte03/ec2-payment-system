# Product Test Checklist

상품 테스트에서는 상품이 주문과 결제의 기준 데이터라는 점을 우선한다. 생성, 수정, 삭제 같은 관리자 기능은 과제 범위 밖이면 테스트 우선순위에서 제외한다.

## 우선순위

1. 상품 목록 조회 성공
2. 카테고리 필터링
3. 최소/최대 가격 필터링
4. 판매 상태 필터링
5. 최신순, 가격 오름차순, 가격 내림차순 정렬
6. 페이지 번호와 페이지 크기 기반 페이지네이션
7. 복합 조건 필터링과 정렬 동시 적용
8. 상품 단건 상세 조회
9. 존재하지 않는 상품 조회 실패
10. 목록 응답과 상세 응답의 필드 범위 차이

## 상품 목록 조회

- 카테고리, 최소 가격, 최대 가격, 판매 상태 조건이 각각 적용되는지 검증한다.
- 여러 필터를 함께 전달해도 조건이 누락되지 않는지 검증한다.
- 최신순, 가격 오름차순, 가격 내림차순 정렬이 문서의 파라미터와 일치하는지 검증한다.
- 페이지 번호와 페이지 크기를 적용했을 때 응답 항목, 전체 개수, 페이지 메타데이터가 일관되는지 검증한다.
- 목록 응답에 상품명, 판매가, 재고 수량, 카테고리, 판매 상태 등 결제 전 화면에 필요한 기본 정보가 포함되는지 검증한다.

## 상품 단건 조회

- 존재하는 상품 ID로 조회하면 목록 조회보다 상세한 정보가 포함되는지 검증한다.
- 상품 설명처럼 상세 화면 전용 필드가 응답에 포함되는지 검증한다.
- 존재하지 않는 상품 ID는 프로젝트 공통 예외 응답 형식으로 실패하는지 검증한다.

## 테스트 계층 선택

- Controller 테스트는 쿼리 파라미터, 응답 JSON 구조, HTTP 상태를 검증한다.
- Repository 테스트는 직접 작성한 필터링, 정렬, 페이징 쿼리가 있을 때 우선 작성한다.
- Service 테스트는 상품 조회 정책이나 응답 조립 로직이 Service에 있을 때 작성한다.
