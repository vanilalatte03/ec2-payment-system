# Payment Test Checklist

결제 시스템에서는 테스트 개수보다 돈, 상태, 멱등성, 소유권, 트랜잭션 정합성을 우선 검증한다.

## 우선순위

1. 결제 확정 성공
2. 결제 금액 불일치
3. 중복 결제 확정
4. 환불 성공
5. 중복 환불
6. 포인트 부족
7. 소유권 검증 실패
8. Webhook 중복 수신
9. 주문 상태 불일치
10. 외부 결제 API 실패
11. 트랜잭션 롤백 필요 케이스

## 결제

- 결제 확정은 서버가 PortOne 조회 결과를 기준으로 처리하는지 검증한다.
- 주문 금액과 PG 승인 금액이 다르면 실패하는지 검증한다.
- 이미 완료된 결제 확정 요청이 중복 처리되지 않고 같은 최종 상태로 수렴하는지 검증한다.
- 포인트 전액 결제처럼 PG 금액이 0인 경우에도 결제 확정 흐름이 안전한지 검증한다.

## 환불

- 환불 가능한 결제 상태에서만 환불되는지 검증한다.
- 부분 환불과 전액 환불의 주문 상태, 결제 상태가 올바른지 검증한다.
- 이미 환불된 항목이나 수량 초과 환불이 중복 처리되지 않는지 검증한다.
- 포인트 환불 금액과 PG 환불 금액이 원 결제 비율에 맞게 계산되는지 검증한다.

## 포인트

- 포인트 부족 시 주문 또는 결제 생성이 실패하는지 검증한다.
- 결제 실패나 환불 시 포인트 사용, 복구, 적립 취소 내역이 원장에 일관되게 남는지 검증한다.
- 환불로 적립 포인트를 회수할 때 프로젝트 정책과 문서가 일치하는지 검증한다.

## 주문과 소유권

- 주문 소유자가 아닌 사용자의 결제 확정, 환불, 조회 요청이 실패하는지 검증한다.
- 결제 확정 전후 주문 상태 전이가 문서와 일치하는지 검증한다.
- 주문 금액, 주문 상품 가격 스냅샷, 수량 기준 계산이 일관되는지 검증한다.

## 웹훅

- 같은 `portonePaymentId` 웹훅이 중복 수신되어도 최종 상태가 동일한지 검증한다.
- 웹훅 payload를 최종 근거로 신뢰하지 않고 PortOne 조회 결과를 기준으로 처리하는지 검증한다.
- 클라이언트 결제 확정 요청과 웹훅 순서가 바뀌어도 같은 최종 상태로 수렴하는지 검증한다.

## 외부 API와 트랜잭션

- 외부 결제 API 실패 시 결제, 주문, 포인트 상태가 애매하게 남지 않는지 검증한다.
- DB 갱신과 외부 API 호출 경계가 필요한 경우 트랜잭션 롤백 또는 보상 처리가 문서화된 기대 동작과 일치하는지 검증한다.
