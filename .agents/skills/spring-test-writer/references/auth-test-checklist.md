# Auth Test Checklist

인증 시스템에서는 테스트 개수보다 계정 식별, 자격 증명 검증, 권한 경계, 토큰 수명, 실패 응답의 안전성을 우선 검증한다.

## 우선순위

1. 회원가입 성공
2. 중복 이메일 또는 중복 계정 식별자
3. 비밀번호 정책 위반
4. 로그인 성공
5. 로그인 자격 증명 불일치
6. 비활성, 탈퇴, 잠금 계정 로그인 차단
7. 인증 필요 API의 미인증 요청 차단
8. 권한 부족 요청 차단
9. 토큰 만료, 변조, 재사용 실패
10. 로그아웃 또는 토큰 재발급 후 이전 토큰 무효화
11. 인증 실패 응답의 정보 노출 방지

## 회원가입

- 필수 값, 이메일 형식, 비밀번호 정책 위반 시 실패하는지 검증한다.
- 중복 이메일, 중복 사용자명, 중복 전화번호처럼 프로젝트의 계정 식별자가 중복될 때 실패하는지 검증한다.
- 비밀번호가 평문으로 저장되지 않고 해시 저장 정책을 따르는지 검증한다.
- 회원가입 성공 후 기본 권한, 상태, 포인트 등 초기 값이 문서와 일치하는지 검증한다.

## 로그인

- 올바른 자격 증명으로 로그인하면 기대한 응답과 토큰 또는 세션이 발급되는지 검증한다.
- 이메일, 사용자명, 비밀번호가 틀린 경우 실패하는지 검증한다.
- 존재하지 않는 계정과 비밀번호 불일치 응답이 계정 존재 여부를 과도하게 노출하지 않는지 검증한다.
- 비활성, 탈퇴, 잠금 계정은 로그인되지 않는지 검증한다.

## 인증과 인가

- 인증이 필요한 API는 토큰 또는 세션이 없으면 실패하는지 검증한다.
- 권한이 부족한 사용자가 관리자, 소유자 전용, 결제/주문 소유자 전용 API를 호출하면 실패하는지 검증한다.
- 본인 리소스와 타인 리소스 접근 결과가 명확히 구분되는지 검증한다.
- 인증 객체에서 사용하는 사용자 식별자가 요청 본문이나 파라미터보다 신뢰 우선순위가 높은지 검증한다.

## 토큰과 세션

- 만료된 토큰, 변조된 토큰, 잘못된 서명 토큰이 거부되는지 검증한다.
- 로그아웃, 비밀번호 변경, 토큰 재발급 이후 이전 토큰 처리 정책이 문서와 일치하는지 검증한다.
- refresh token이 있다면 재사용, 탈취 의심, 만료 케이스가 안전하게 실패하는지 검증한다.
- access token과 refresh token의 수명과 저장 위치가 프로젝트 정책과 일치하는지 검증한다.

## 실패 응답과 보안 경계

- 인증 실패와 인가 실패가 프로젝트 공통 응답 형식과 HTTP 상태 코드를 따르는지 검증한다.
- 실패 응답에 비밀번호, 토큰, 내부 예외, 계정 존재 여부 같은 민감 정보가 노출되지 않는지 검증한다.
- 인증 관련 테스트는 단순 Controller status 검증에 그치지 말고 Security filter, 인증 principal, 권한 판단 지점 중 실제 위험 지점을 함께 확인한다.
