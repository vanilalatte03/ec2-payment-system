# Payment Domain Review Checklist

## Order

* 주문 생성 시 상태가 `PENDING` 또는 `결제 대기`인지
* 주문 완료는 결제 검증 이후에만 되는지
* 주문 상품에 주문 당시 상품명/가격 스냅샷이 저장되는지
* 다중 상품 주문에서 총액 계산이 정확한지
* 주문 소유권 검증이 있는지

## Payment

* 결제 시도 레코드가 먼저 생성되는지
* `portonePaymentId`가 unique인지
* 클라이언트 결제 성공값을 그대로 신뢰하지 않는지
* PortOne 결제 조회 결과를 기준으로 확정하는지
* 주문 금액과 PG 승인 금액을 비교하는지
* 결제 상태와 주문 상태가 분리되어 있는지
* 중복 confirm 요청에 안전한지

## Refund

* 부분 환불과 전액 환불을 모두 지원하는지
* 환불 가능 상태를 검증하는지
* 이미 환불된 결제에 대한 멱등성이 있는지
* 선검증 후 DB 갱신을 먼저 커밋하고 PG 취소 호출을 트랜잭션 밖에서 수행하는지
* Refund 이력을 별도 테이블에 남기는지
* 환불 실패 시 상태가 애매하게 남지 않는지

## Webhook

* PortOne 이벤트 식별자를 안정적으로 받을 수 있는 경우에만 `webhookId`를 unique하게 저장하고, 기본 멱등성은 `portonePaymentId`와 상태 기반으로 보장하는지
* Webhook payload를 최종 근거로 믿지 않는지
* Webhook 수신 후에도 PortOne 결제 조회를 수행하는지
* Client Confirm과 동일한 결제 확정 로직을 재사용하는지
* 이미 처리된 이벤트에 대해 안전하게 200 OK를 반환하는지

## Point

* 포인트 잔액 스냅샷과 거래 내역이 분리되어 있는지
* 포인트 사용, 적립, 복구, 취소 타입이 명확한지
* 결제 실패 시 사용 포인트가 잘못 차감된 상태로 남지 않는지
* 환불 시 사용 포인트 복구와 적립 포인트 취소가 처리되는지
* 포인트 부족 검증이 있는지

## Membership

도전 기능이 포함된 경우 다음을 확인한다.

* 등급 정책 기준이 명확한지
* 총 결제 금액 기준이 결제 완료 건만 포함하는지
* 환불된 결제는 등급 산정에서 제외되는지
* 결제 완료/환불 후 등급 재계산이 수행되는지

## Subscription

도전 기능이 포함된 경우 다음을 확인한다.

* Plan, PaymentMethod, Subscription, SubscriptionInvoice가 분리되어 있는지
* billingKey가 로그나 응답에 노출되지 않는지
* 구독 상태가 명확한지: `TRIALING`, `ACTIVE`, `PAST_DUE`, `CANCELED`, `ENDED`
* 스케줄러가 결제 대상 구독만 조회하는지
* 동일 구독/동일 청구 기간 중복 결제가 방지되는지
* 구독 해지가 이후 자동 결제를 막는 구조인지
